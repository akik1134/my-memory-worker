# DOC-002_GitHub知識ベース運用規約

Version: 1.0

目的：

D1OS開発で得られた知識をGitHubへ整理保存し、
将来のPC変更・AI変更・開発再開時でも利用できる状態を維持する。

---

# 1. 基本方針

GitHubをD1OS開発の知識保存場所として利用する。

保存対象：

- 開発手順
- 環境構築方法
- エラー解決方法
- 設計判断
- AI共同開発ルール
- 復元情報

ただし、すべての情報を保存しない。

将来再利用できる重要情報のみ保存する。

---

# 2. 保存基準

保存する情報：

- 再発する可能性がある問題
- 環境構築手順
- 解決方法
- 設計変更理由
- 長期的に利用する知識

保存しない情報：

- 一時的な会話
- 完了後不要な説明
- 重複した内容

---

# 3. 文書管理ルール

基本：


1文書 = 1目的


とする。

1つの文書へすべてを詰め込まない。

---

# 4. 命名規則

形式：


DOC-番号_名前.md


例：


DOC-001_X11開発環境構築ガイド.md

DOC-002_GitHub知識ベース運用規約.md


番号は重複させない。

---

# 5. 更新ルール

変更後：

確認：

```bash
git status
```

保存：

```bash
git add .
```

記録：

```bash
git commit -m "変更内容"
```

同期：

```bash
git push
```

## 5.1 保存タイミング

以下の場合は、必ず知識として保存する。

- 環境構築手順を確定したとき
- エラーの原因と解決方法が分かったとき
- 設計判断を変更したとき
- 今後再利用しそうな作業手順ができたとき

## 5.2 保存前の確認

保存前に、次の3点を確認する。

1. その情報が将来再利用されるか
2. 既存文書と重複していないか
3. 1文書に1目的で整理できるか

---

# 6. AI共同開発時の保存

ChatGPTとの開発で重要な情報が発生した場合、

会話だけに残さない。

保存対象：

- 決定した設計
- 解決した問題
- 再利用可能な手順

↓

GitHubへ保存する。

---

# 7. Migrationとの関係

スレッド移行時は、

会話全文を移動しない。

必要情報のみMigration Exportで引き継ぐ。

参照例：


DOC-001確認済み

DOC-002確認済み

Runtime Export確認済み


---

# 8. 新情報管理

新しい情報：

↓

一時保存

↓

開発メモへ記録

↓

必要性判断

↓

正式DOC化

という流れにする。

---

# 9. 情報肥大化防止

禁止：

- 同じ内容の文書を複数作成
- 1文書へ大量情報を追加
- 目的不明の巨大資料作成

---

# 10. 完成条件

このルールが機能している状態：


必要な情報を探せる

新しい情報を追加できる

PC変更でも復元できる

AIが参照できる

文書が肥大化しない


---

# D1OS Knowledge Base Rule

目的：

情報を保存することではなく、

未来の開発を再開できる知識基盤を作ることである。
