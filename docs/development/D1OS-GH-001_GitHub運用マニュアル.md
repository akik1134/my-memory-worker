# D1OS-GH-001

# GitHub運用マニュアル

Version: 1.0

---

## 1. 目的

本マニュアルは、D1OS開発においてGitHubを利用する際の標準的な作業手順を定義する。

目的は、

- 毎回同じ方法で登録・更新できる
- 迷わず作業できる
- AIと共通の手順で開発できる
- トークン消費を抑えながら作業できる

ことである。

---

## 2. 適用範囲

本マニュアルは、次の内容に適用する。

- Knowledge Base
- Migration
- README
- 設計資料
- 運用資料
- その他D1OS文書

---

## 3. 基本方針

GitHubは、D1OS開発の作業履歴・文書・設定情報を管理する共通の作業基盤とする。

基本ルールは次のとおりである。

- 変更内容は必ずGitHubに反映する
- 1つの作業は1つの目的に集約する
- 重要な判断や手順は文書として残す
- 変更前後の状態を確認してから保存する

---

## 4. 標準作業フロー

### 4.1 作業開始前

1. 変更内容を確認する
2. 既存の文書やコードと重複していないか確認する
3. 必要ならブランチを作成する

### 4.2 変更作業

1. 対象ファイルを編集する
2. 内容が重複していないか確認する
3. 変更理由が分かるように整理する

### 4.3 保存と共有

保存時は、次の順で行う。

```bash
git status
git add .
git commit -m "変更内容"
git push
```

---

## 5. ブランチ命名規則

ブランチ名は、内容が分かるように次の形式で作成する。

- feature/機能名
- fix/修正内容
- docs/文書名
- chore/整理内容

例：

- feature/task-api
- fix/login-error
- docs/github-manual

---

## 6. コミットルール

コミットメッセージは、簡潔かつ内容が分かるように記載する。

形式例：

- add: 〇〇を追加
- update: 〇〇を更新
- fix: 〇〇を修正
- docs: 〇〇の文書を追加

例：

```bash
git commit -m "docs: GitHub運用マニュアルを追加"
```

---

## 7. 文書更新時のルール

文書を更新する際は、次を守る。

- 変更理由を明記する
- 既存の文書と重複しないようにする
- 1文書 = 1目的を基本とする
- 重要な手順は再利用できる形で残す

---

## 8. AI共同開発時の運用

AIと共同開発する場合は、次の点を重視する。

- 会話だけに留めず、重要な内容はGitHubへ保存する
- 変更内容の背景を残す
- 再利用可能な手順は文書化する
- 迷った場合は既存ルールに戻す

## 11. GitHub登録標準手順

新しい文書や変更内容をGitHubへ登録するときは、必ず次の手順で行う。

### 11.1 文書作成

1. 保存場所を決める
2. ファイル名を決める
3. Markdown形式で保存する
4. 内容を入力して保存する

### 11.2 変更内容の確認

1. 変更対象ファイルを確認する
2. 追加・修正・削除の内容を把握する
3. 既存文書との重複がないか確認する

### 11.3 VS Code から反映

1. VS Code の「ソース管理」を開く
2. 変更されたファイルを確認する
3. 変更ファイルをステージする

### 11.4 コメント入力

1. コメント欄に変更内容を日本語で入力する
2. 例：
   - DOC-001追加
   - Migration更新
   - README修正

### 11.5 コミット

1. 「コミット」を実行する
2. 変更内容が記録されることを確認する

### 11.6 GitHub へ送信

1. 「同期」または「Push」を実行する
2. GitHub 上で反映されることを確認する

### 11.7 確認作業

PowerShell で次を実行する。

```bash
git status
```

結果が次の状態であれば登録完了とする。

```text
nothing to commit, working tree clean
```

# Git運用ルール（Version1）

通常開発では以下の手順を標準とする。

1. ファイルを編集
2. 保存（Ctrl + S）
3. git add
4. git commit -m "内容"
5. git push
6. git status
