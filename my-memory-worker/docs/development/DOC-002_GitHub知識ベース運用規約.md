# DOC-002_GitHub知識ベース運用規約

Version: 1.1

---

## 目的

D1OS開発で得られた知識をGitHubへ整理保存し、
将来のPC変更・AI変更・開発再開時でも利用できる状態を維持する。

---

## 1. 基本方針

GitHubをD1OS開発の知識保存場所として利用する。

保存対象は、次のとおりとする。

- 開発手順
- 環境構築方法
- エラー解決方法
- 設計判断
- AI共同開発ルール
- 復元情報

ただし、すべての情報を保存しない。将来再利用できる重要情報のみ保存する。

---

## 2. 保存基準

### 保存する情報

- 再発する可能性がある問題
- 環境構築手順
- 解決方法
- 設計変更理由
- 長期的に利用する知識

### 保存しない情報

- 一時的な会話
- 完了後に不要になった説明
- 重複した内容
- 目的のない大きなメモ

---

## 3. 文書管理ルール

基本として、1文書 = 1目的とする。

1つの文書にすべてを詰め込まない。

---

## 4. 命名規則

形式は次のとおりとする。

- DOC-番号_名前.md
- D1OS-GH-番号_名前.md

例：

- DOC-001_X11開発環境構築ガイド.md
- DOC-002_GitHub知識ベース運用規約.md
- D1OS-GH-001_GitHub運用マニュアル.md

番号は重複させない。

---

## 5. 更新ルール

変更後は、次の順で確認・保存・共有する。

```bash
git status
git add .
git commit -m "変更内容"
git push
```

### 5.1 保存タイミング

以下の場合は、必ず知識として保存する。

- 環境構築手順を確定したとき
- エラーの原因と解決方法が分かったとき
- 設計判断を変更したとき
- 今後再利用しそうな作業手順ができたとき

### 5.2 保存前の確認

保存前に、次の3点を確認する。

1. その情報が将来再利用されるか
2. 既存文書と重複していないか
3. 1文書に1目的で整理できるか

---

## 6. AI共同開発時の保存

AIとの開発で重要な情報が発生した場合、会話だけに残さず、GitHubへ保存する。

保存対象例：

- 決定した設計
- 解決した問題
- 再利用可能な手順
- 運用上重要な判断

---

## 7. Migrationとの関係

スレッド移行時は、会話全文を移動しない。必要情報のみMigration Exportで引き継ぐ。

参照例：

- DOC-001確認済み
- DOC-002確認済み
- Runtime Export確認済み

---

## 8. 新情報管理

新しい情報は、次の流れで扱う。

1. 一時保存
2. 開発メモへ記録
3. 必要性を判断
4. 正式な文書として整理

---

## 9. 情報肥大化防止

次の行為は禁止する。

- 同じ内容の文書を複数作成すること
- 1文書へ大量情報を追加すること
- 目的不明の巨大資料を作ること

---

## 10. 完成条件

このルールが機能している状態は、次のとおりである。

- 必要な情報を探せる
- 新しい情報を追加できる
- PC変更でも復元できる
- AIが参照できる
- 文書が肥大化しない

---

## 11. AI参照の基本ルール

AIは、作業前に次の順で情報を確認する。

1. Migration Export
2. AI INDEX
3. 必要な開発文書
4. README

推測による補完は行わない。

---

## 12. フォルダ名の注意

D1OSでは、似た名前のフォルダを役割で区別する。

### migration

用途：

- D1OS開発状態の引き継ぎ情報保存

保存内容：

- Runtime Export
- Thread Migration
- Resume情報

### migrations

用途：

- Cloudflare D1 Databaseの変更履歴保存

保存内容：

- SQL Migration File
- Database Schema変更履歴

注意：

- migration と migrations は別用途である
- 役割を混同しない

- 役割が異なるフォルダは、名前だけで意味が分かるようにする。
- 似た語を使う場合は、用途を明示する。
- 例：
  - migration: 開発状態の引き継ぎ情報
  - migrations: D1 Database の変更履歴

このルールにより、同じように見えるフォルダでも用途を混同せずに管理できる。

migration と migrations は別用途であり、
混同しない。

## 13. D1OS標準ルール（実運用ルール）

実運用で得られた以下の6ルールを、D1OSの標準ルールとして正式に追加する。

### 13.1 1サイクル完結ルール

1つの作業工程は、次の流れで完結させる。

1. 編集する
2. 保存する
3. Git保存する
   - git add
   - git commit
   - git push
4. git status で確認する

AIは工程の途中で終了せず、可能な限りこの1サイクルを1回の指示で完結させる。

これにより、保存漏れ・コミット忘れ・Push忘れを防ぎ、不要な確認往復を減らす。

### 13.2 未回答禁止ルール

ユーザーから複数の質問・指摘・改善案があった場合、AIは新しい作業へ進む前に、すべてへ回答・反映する。

回答漏れを残したまま次工程へ進まない。

### 13.3 重複回答禁止ルール

一度回答済みの内容は繰り返し説明しない。追加情報がある場合のみ補足する。

トークン節約を優先する。

### 13.4 初心者操作説明ルール

AIは、どのソフトを開くか・どのボタンを押すか・どこへ保存するかまで具体的に説明する。

初心者でも迷わず実行できることを最優先とする。

### 13.5 作業単位最適化ルール

1工程は「確認が必要になる直前」までまとめて行う。

細かく区切り過ぎず、リスクが上がり過ぎない範囲で効率よく進める。

### 13.6 Git保存情報同時出力ルール

GitHubへ保存する工程では、毎回次を同時に提示する。

- git commitメッセージ
- GitHubコメント（日本語）
- 実行するPowerShellコマンド
- 完了確認コマンド

ユーザーが追加で質問しなくても、その工程を最後まで完了できる状態を標準とする。
